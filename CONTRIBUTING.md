# Contributing

Thanks for helping. Contributions arrive as pull requests, and the owner reviews every one.

1. Fork the repository and create a branch for one change.
2. Make the change and test it ([docs/Testing.md](docs/Testing.md) lists the suites and the expected counts).
3. Open a pull request and fill in the template: what changed, why, how you tested it.

Report bugs as issues: what you did, what you expected, what happened, and the version (`VisualBeefEditor.exe --version`).
Security problems go through [SECURITY.md](SECURITY.md), not an issue.

UI text: use the project's own words from [docs/Vocabulary.md](docs/Vocabulary.md) in labels, menus, messages and docs
(Sheet, Outline, Type Settings, Properties, Project Browser). Do not use another tool's terms for them.
For UI changes, run the editor and check the screens you changed (1280 and 1920 wide, 125% scaling, both themes).

Documentation: only pages written for users belong in this repository. Please do not add plans, roadmaps or internal notes
to a pull request.
